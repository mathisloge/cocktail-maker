# Goals and Quality Scenarios Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the quality goals measurable with the arc42 quality model Q42: chapter 1 gets the requirements overview and the stakeholders, the goals get Q42 tags, chapter 10 gets a quality tree, a traceability table and owner-confirmed quality scenarios (`QS-nn`).

**Architecture:** AsciiDoc sections in a fixed template, read by pytest readers. Content is drafted in the scratchpad, checked by three reviewers on the most capable model, confirmed by the owner, and only then committed.

**Tech Stack:** Antora 3, AsciiDoc, D2 through Kroki, pytest, the `cocktail-maker-docs` plugin.

**Spec:** `docs/superpowers/specs/2026-11-15-quality-design.md` (read "The quality model" first: Q42 replaced ISO/IEC 25010)

## Global Constraints

- **Branch:** every agent first runs `git branch --show-current`, which must print `docs-quality`, and never switches branches.
- **Use our skills:** load `cocktail-maker-docs:architecture-docs`, `cocktail-maker-docs:writing-diagrams` and `cocktail-maker-docs:writing-style` with the Skill tool before writing.
- **Commit messages carry NO `Co-Authored-By:` trailer.** Conventional messages, explicit paths. **Never stage** `hw_simulator/client.cppm`, `.claude/settings.json`, `.superpowers/` or `CLAUDE.md`.
- **No unconfirmed content:** chapter 1 text, goal tags and scenarios are committed only after the owner confirmed them.
- **Owner rules:** no implementation details, no "owner decision"/"user decision" as a source, no fact without a docs page or ADR.
- **Q42 tags:** `#efficient`, `#flexible`, `#maintainable`, `#operable`, `#reliable`, `#safe`, `#secure`, `#suitable`, `#usable`.
- **Scenario template** (spec): `[[QS-nn]]`, `== QS-nn: <title>`, then `Goal::`, `Q42::`, `Source::`, `Stimulus::`, `Artifact::`, `Environment::`, `Response::`, `Measure::`, `Verification::`, `Value::`, `State::`, `Checks::` in this order; a value may run over lines until the next field.
- **Verification:** `Test`, `Inspection`, `Analysis` or `Demonstration`. **States:** `Target` (owner only), `Provisional`, `Open`, `Withdrawn`; `Value:: none` exactly for `Open` and `Withdrawn`, otherwise `<number> <unit>` or a count with a noun.
- **Checks:** xrefs only, to defined `IF-nn`/`IF-nn-Rnn`, to scenario anchors on `runtime-view.adoc`/`fault-scenarios.adoc`, to ADR pages (System, Station checked; Mechanics accepted).
- **30 s limits:** the pour limit and the calibration run limit are provisional wherever they appear: "provisional, to be confirmed on the assembled machine" in prose, "(provisional)" in a diagram label; keep existing `(open, …)` label parts.

## Review Focus

1. **A Q42 tag that does not exist, or a scenario with no tag of its goal:** reported. Test in Task 1.
2. **A Value/State mismatch, or a value without a unit:** reported. Test in Task 1.
3. **A Checks xref to a removed requirement, a wrong scenario anchor or a missing ADR page:** reported. Test in Task 1.
4. **Tree, table and sections out of step** (a QS in one but not the other, a different state or value in the table): reported. Test in Task 1 (bites from Task 5).
5. **A number that looks decided but is not:** the faithfulness reviewer checks every number; the 30 s test covers the known cases (Task 1).
